# Historical replay spend admission

Run `python scripts/preflight_historical_replay.py YYYY-MM-DD` with the production catalog DSN to inspect a day before replay. The command reads saved catalog references and coverage. It does not fetch article bodies, start provider calls, publish a report, or mutate the catalog. `article_version_ids` are the exact saved inputs currently selected for that day. Pending summary and sentiment counts become available after clustering. The remaining spend estimate uses a $0.0041 per-call proxy from recent report-linked relevance calls, so it is directional rather than a quote for the whole replay.

`ARCHIVE_DAY_SPEND_LIMIT_USD` defaults to `10`. Each provider call in retrospective analysis reserves the day's entire remaining allowance in PostgreSQL before it runs. The provider SDK does not retry internally for these calls. A second replay cannot start a paid call while that reservation is open. When the provider returns a measured cost, the reservation settles to that cost and the next call can proceed. Provider failures and responses without a measured cost leave the allowance held, because their charge is unknown. A replay at its limit stops before another call and remains unpublished. The automated selector skips capped days so later days can proceed.

The limit controls admission, not the provider's final invoice. A single provider response can cost more than the remaining allowance; the response is recorded and the replay stops without publishing. Review an unsettled reservation against provider billing before adjusting it. The ledger is durable across Dagster retries and process restarts.
